# 测试与质量

## 无界面自检（--selftest）

程序内置无界面自检，验证核心逻辑与数据完整性，是 CI/回归的第一道闸门：

```bash
typing --selftest     # 退出码 0 为通过
# 或
make selftest
```

### 检查内容

1. **词典加载**：三张数据表（字/词/拼音）能否从 Qt 资源加载成功。
2. **单字抽查**：`五 笔 字 型 输 入 法` 的字须同时给出五笔全码与拼音（如 `五=gghg/wǔ`）。
3. **分词**：示例句的分词结果打印（词列表可见）。
4. **词语编码**：`人工智能 → watc`。
5. **回归：常见词/领域词必须成词**：对包含 `计划 / 应用 / 市场 / 人工智能 / 自动驾驶 / 金融科技` 的句子做分词，任一未成词即 FAIL——此项专门防止词表截断/缺失问题回归。
6. **文章库**：内置文章 ≥ 20 篇，逐篇打印序号、标题、字数。
7. **双语数据（0.2.0）**：20 篇内置文章均须有英文译文；逐句中英对照总数 ≥ 800；
   英文单词释义抽查（artificial / blockchain / money / principle / stages）齐全。

除 `--selftest` 外，另有两条专项自检链路（0.2.1 起按文件拆分，位于 `src/selftest.cpp`、
`src/imetest.cpp`、`src/entest.cpp`）：

- `--ime-test`：用与真实输入法相同的 `QInputMethodEvent` 提交路径逐字模拟输入，
  验证连续输入、出错截断、截断后继续三条链路（0.1.9 回归防线）。
- `--en-test`：英文逐词匹配自检——连续 80 字符全对、出错截断、截断后继续（0.2.0）。

新增数据或修改逻辑后，若改变了以上任一行为，应同步更新自检断言。

## 如何新增回归检查

在 `src/selftest.cpp` 的 `runSelfTest()` 中追加断言即可，例如：

```cpp
// 例：断言某个新词必须被切分
const QString s = QStringLiteral("……包含新词……");
// 分词后 words.contains(新词) 否则 fprintf FAIL 并 return 1
```

自检保持**无界面**（不依赖 GUI），便于 CI 与脚本调用。

## 验证方式清单（开发流程）

| 层次 | 方式 | 说明 |
| --- | --- | --- |
| 逻辑 | `--selftest` | 数据、编码、分词、文章完整性、双语数据 |
| 输入链路 | `--ime-test` / `--en-test` | 输入法逐字提交、英文逐词匹配（含出错截断） |
| GUI | 启动程序运行数秒无崩溃 | 覆盖窗口/资源加载/各标签页初始化 |
| 分发 | 干净 PATH 下运行 `dist/` 中的 exe | 验证运行库齐全、可独立运行 |
| 数据 | `_data/` 下审计脚本 | 常见词覆盖、词语编码、分词质量抽样 |

## 已知限制

- 分词为纯正向最大匹配，不保证语言学的完全正确（如个别短语按词典切法可能不是最小切分）；对五笔练习而言，目标是“常用词尽量成词”，已通过词表完整收录 + 领域补充达到该效果。
- 词表来自 86 版五笔码表，极生僻词/新词可能缺失（编码仍可通过取码规则回退给出，但分词不会成词）。
