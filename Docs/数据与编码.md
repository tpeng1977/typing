# 数据与编码

本页说明软件内嵌数据（字、词、拼音、文章）的来源、格式与重新生成方法，以及五笔取码规则。

## 数据来源

| 数据 | 来源 | 许可证/说明 |
| --- | --- | --- |
| 单字/词语五笔码表 | 开源 Rime 方案 `KyleBing/rime-wubi86-jidian` 的 `wubi86_jidian.dict.yaml` | 86 版王码五笔，含全码与各级简码 |
| 拼音 | `mozillazg/pinyin-data` 项目的 `pinyin.txt` | 汉字 → 多音字读音列表 |
| 20 篇练习文章 | 本项目编写（现代科技 10 篇 + 金融 10 篇） | 简体中文，单段式 |

原始文件较大（码表约 1.3 MB、拼音约 1 MB），**不随源码库分发**，重新生成数据前需手动下载：

```bash
curl -L -o _data/wubi86_jidian.dict.yaml \
  https://raw.githubusercontent.com/KyleBing/rime-wubi86-jidian/master/wubi86_jidian.dict.yaml
curl -L -o _data/pinyin.txt \
  https://raw.githubusercontent.com/mozillazg/pinyin-data/master/pinyin.txt
```

（在 Windows 可用浏览器直接下载保存到 `_data/`。）

## 重新生成数据

```bash
python _data/build_data.py
```

脚本做三件事：

1. 解析码表 → `res/wubi_char.txt`（字 + 全码,简码…）与 `res/words.txt`（词 + 编码）；
2. 解析拼音表 → `res/pinyin.txt`；
3. 汇总 `articles/` → `res/articles.json`。

运行后必须重新编译，数据才会进入二进制。

### 关键注意（历史踩坑，勿回归）

- 码表文件数据段以 `...` 结束、自第 27 行起为 `字\t码\t权重` 数据行。解析器按“含制表符且首字段为汉字”判定数据行。
- **禁止用固定条数截断词表**。早期 `keep[:60000]` 导致「计划」「应用」「市场」等高频词在同权重内按文件顺序被切掉、分词不准。现改为**完整收录全部 2–6 字词**。

## 文件格式

### res/wubi_char.txt

```
字\t全码,一级简码,二级简码,...
五	gghg,gg,gggh
```

编码按 `(长度, 字典序)` 排序，**最长的为全码**，其余为简码。

### res/words.txt

```
词\t编码
人工智能	watc
计划	yfaj
```

编码来自码表（若有）；补充词按取码规则计算。

### res/pinyin.txt

```
字\t拼音1,拼音2,...
重	zhong,chong
```

多音字按顺序列出，程序取第一个为默认读音。

### res/articles.json

```json
[{"title":"人工智能的发展与应用","body":"人工智能是一门……"}]
```

## 五笔取码规则（86 版，程序内回退与补充词生成共用）

单字取全码（含简码提示）。词语：

| 字数 | 规则 | 示例 |
| --- | --- | --- |
| 2 | 第 1 字前 2 码 + 第 2 字前 2 码 | 计划 = 计(yf) + 划(aj) = yfaj |
| 3 | 第 1 字首码 + 第 2 字首码 + 第 3 字前 2 码 | 机器人 = 机(s) + 器(k) + 人(ww) = skww |
| 4 | 前 3 字首码 + 末字首码 | 人工智能 = 人(w)+工(a)+智(t)+能(c) = watc |
| 5–6 | 前 3 字首码 + 末字首码 | （同四字规则） |

实现位置：`Dict::computeWordCode`（C++，查询回退）与 `build_data.py` 的 `compute_word_code`（Python，补充词生成）——两处规则必须保持一致。

## 校验脚本

`_data/` 下附带若干一次性校验脚本（开发用）：

- `audit_words.py`：常见词覆盖审计（曾用于定位截断问题）。
- `verify_words.py`：抽查词表是否完整、词语编码是否正确。
- `check_seg.py`：用与 C++ 相同的算法复刻分词，检查文章切分质量。

这些脚本不参与构建，仅作数据质量验证工具。
