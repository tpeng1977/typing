# 更新日志

## 0.2.3 — 2026-10-26

**变更（按用户要求）**
- **错误输入红色显示 + Backspace 可删除**：错误字符不再被立即清除，而是
  在输入区以红色显示（正确部分保持蓝色）。用户可用 Backspace 删除错误字符，
  当前行删完后可继续往上一行删除（跨行使 Backspace 自然回退）。
  - 实现：`processText()` 不再强制 `setText(want)` 清除错误字符，仅在行切换时
    同步输入框；`JustifiedInputLine::paintEvent` 绘制正确部分（蓝）+ 错误部分（红）；
    输入框为空且当前行已删完时自动回到上一行末尾。

## 0.2.2 — 2026-10-26

**变更（按用户要求）**
- **英文输入框与原文行严格对齐**：新增自绘输入框 `JustifiedInputLine`
  （`src/justifiedinput.h/.cpp`），用整行原文计算词间距（与上方 `JustifiedLabel`
  两端对齐算法完全一致），只绘制已输入部分 + 光标，使英文练习时输入区字符
  与上方原文行逐列对齐（此前 QLineEdit 用标准空格，两端对齐拉伸词间距后错位）。
  中文模式自动退化为标准左对齐，不影响中文跟打。
- **标题栏应用图标**：新增五笔主题图标（深蓝圆角底 + 白色"五"字 + 键盘按键
  装饰），注册到 Qt 资源系统（`res/app_icon.png` / `app_icon.ico`），
  `QApplication::setWindowIcon` 设置为窗口图标。

## 0.2.1 — 2026-10-17

**修复（英文/中文练习当前词高亮错位，按用户反馈）**
- **英文练习高亮修复**：输入到单词中部时（如 `machines` 已输入 `mach`），
  原文中该词被错误整词/错位黄底高亮（曾盖住已输入部分）。
  根因：`JustifiedLabel::setTarget` 收到的是「目标词首」+「未输入部分长度」，
  词内输入时高亮区间 `[词首, 词首+未输入长度)` 正好落在已输入的字母上。
  修复：高亮起点改为「未输入部分起点」`max(目标词首, 当前行已输入长度)`，
  已输入部分保持蓝色、未输入部分（含跨行截断）黄底加粗。
- 该修复同时纠正**中文词语模式**的同类问题：输入 `人工` 后，原文中
  `人工` 显示为已输入蓝色、`智能` 黄底加粗（此前黄底会盖住已输入部分）。

**变更（英文两端对齐 + 源码拆分，按用户要求）**
- **英文练习两端对齐（justify）**：新增自绘行标签 `JustifiedLabel`
  （`src/justifiedlabel.h/.cpp`），英文练习行按空格切词，将行内富余宽度均摊到
  词间空格，实现类似 Word 的**两端对齐**（右缘整齐）；段落最后一行保持左对齐，
  中文行（无词间空格）不受影响。
- **源码拆分**：将过大的源文件按功能模块拆成多个小文件，便于跟踪：
  - `practice.cpp`（938 行）→ `practice.cpp`（界面构建/生命周期/计时暂停）+
    `practice_lines.cpp`（Word 式折行 + 英文按词折行）+
    `practice_match.cpp`（输入匹配核心 + 目标/编码/释义查询）+
    `practice_render.cpp`（行标签/右侧对照/统计渲染）；
  - `main.cpp`（352 行）→ `main.cpp`（入口与命令行分发）+
    `selftest.cpp`（`--selftest`）`imetest.cpp`（`--ime-test`）`entest.cpp`（`--en-test`）；
  - 新增 `practice_internal.h` 共享内部常量与 HTML 转义工具。
  - 拆分仅调整文件组织，**不改动任何逻辑**；clean 全量重编译后
    `--selftest` / `--ime-test` / `--en-test` 均 exit 0，GUI 中文/英文练习链路复验通过。

## 0.2.0 — 2026-10-17

**新增（中英双语练习 + 版本信息，按用户要求）**
- **20 篇内置文章全部配齐英文译文**：逐句切分中英对照（共 806 句），
  数据存于 `res/data/sentences.json`（中文句含原文起始偏移）；英文单词释义 4,023 词
  存于 `res/data/enwords.json`；两者经 Qt 资源系统嵌入可执行文件。
- **语言切换**：练习页顶部下拉切换「中文练习 / 英文练习」。
  - 练习中文：逐字匹配中文原文，**右侧高亮显示当前中文句对应的英文译文**
    （当前句黄底加粗、前后句灰色，随进度自动滚动）。
  - 练习英文：逐词匹配英文译文，**右侧高亮当前英文句对应的中文译文**，
    提示区显示当前要输入单词的**中英双解含义**（如 `Artificial · 释义 人工的`）；
    进度与速度按字符计。
  - 英文模式同样采用「原文在上、输入在下」的逐行排版（按词折行、不在词中断行），
    与中文模式的整齐行对结构一致。
- **英文折行修复**：修复英文正文曾被渲染为连续长段一行的 bug（折行宽度未累积），
  现按可用宽度正确折行，行对结构与中文一致。
- **阅读打开不再重置练习进度**：文章库双击/「打开所选文章」只打开阅读页，
  不重置练习页进度；「开始练习」才会加载文章并重置。
- **版本信息显示**：窗口标题栏与状态栏常驻显示**代码版本与编译时间**
  （`buildinfo.h` 定义 `APP_VERSION`，编译时自动记录 `__DATE__/__TIME__`）。
- 自检扩展：`--selftest` 增加双语数据校验（20 篇均有译文、4,023 词均有释义）；
  新增 `--en-test` 英文逐词匹配自检（连续正确、出错截断、截断后继续）。

## 0.1.9 — 2026-10-16

**修复（逐字输入被吞 / 输入一两个字后输入区不再接收新字符）**
- 0.1.8 为支持跨行词组，把输入匹配起点从“当前行行首”改为“当前位置（absPos）”，
  但输入框内容是从**当前行行首累积**的（含已匹配前缀），二者错位导致：
  真实输入法逐字输入时，第二个字起前缀比对失败并被截断回原样，
  表现即“输入一个字/两个字后输入区不再接收新字符”。
- 0.1.9 将匹配起点改回**当前行行首** `lineStarts_[lineIdx_]`，与输入框“行首累积”语义一致；
  跨行词组能力不变（输入框与“行首到文末的连续正文”前缀匹配，仍可一次输入跨行词组）。
- 同时保留：单行内连续正确输入时不再重写输入框（避免干扰系统输入法），
  仅在跨行截断 / 出错截断时改写输入框。
- 新增 `--ime-test` 自检模式：用与真实输入法相同的 `QInputMethodEvent` 提交路径
  逐字模拟输入，验证连续输入、出错截断、截断后继续输入三条链路。

## 0.1.8 — 2026-10-16

**变更（跨行词组整词输入 + 用时时分秒，按用户要求）**
- **支持跨行词组一次输入**：匹配不再限于单行，而是与“当前位置到文末的连续正文”做前缀匹配——
  当词被折行拆开（上一行行尾 + 下一行行首组成词组，如 `…五十年代的一次` / `夏季研讨会…`）时，
  提示仍显示完整词组，用户可一次性连续输入整词，自动跨越行边界前进；
  输入框只保留当前行已匹配部分，逐字正确计数不变。
- **用时改为时分秒**：统计栏「用时」由“N 秒”改为 `时:分:秒`（如 `0:00:00`、`1:02:03`）。
- 内部修复：程序性改写输入框（换行、重开、缩放重排）不再触发重复匹配，
  避免跨行场景下输入框内容与当前位置不一致导致的误扣正确数。

## 0.1.7 — 2026-10-16

**变更（Word 式换行与段落缩进，按用户要求）**
- **整段按可用宽度自然折行**：同一段不再按句末标点/字数硬断，改为像 Word 文档一样
  让文字流自然填满每一行，行满宽度、左右对齐（CJK 全角字天然齐边），
  消除了此前“行尾孤字/碎片行”（如 `成。`、`品，只能靠以物易物。`）的问题。
- **每段首行缩进两字符**：当前行卡片、已完成行与后续行均按段落首行缩进；
  缩进通过左内边距实现、不进入匹配文本；首行按“可用宽度 − 缩进”折行，
  保证右边缘与其他行对齐。输入框同步左移，与缩进的原文对齐。
- **窗口缩放自动重排**：宽度变化时按绝对位置重建各行并原样恢复当前行与已输入内容，
  练习进度不丢失；字号统一为 20px。
