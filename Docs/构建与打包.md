# 构建与打包

## 前置依赖

- **CMake ≥ 3.16**
- **Qt 6.5+（Widgets 组件）**
- 平台编译器：Windows 用 MinGW 或 MSVC；macOS 用 Clang/Xcode；Linux 用 GCC/Clang

## 用 Makefile 构建（推荐）

工程根目录的 `Makefile` 包装了 CMake，提供常用目标：

| 目标 | 作用 |
| --- | --- |
| `make` / `make build` | 配置 + 编译（Release） |
| `make configure` | 仅配置 |
| `make run` | 运行程序 |
| `make selftest` | 无界面自检（退出码 0 为通过） |
| `make dist` | 打包到 `dist/`（自动部署 Qt 运行库） |
| `make clean` / `make distclean` | 清理构建目录 / 构建+分发目录 |

首次配置需要把 Qt 与生成器信息传给 CMake，通过 `CONFIGURE_FLAGS` 传入（生成器已缓存后无需重复）：

```bash
# Windows + MinGW + Ninja + Qt 6.5.3
make CONFIGURE_FLAGS="-G Ninja -DCMAKE_PREFIX_PATH=C:/Qt/6.5.3/mingw_64"

# macOS（Homebrew Qt）
make CONFIGURE_FLAGS="-DCMAKE_PREFIX_PATH=/opt/homebrew/opt/qt"

# Linux（系统 Qt）
make CONFIGURE_FLAGS="-DCMAKE_PREFIX_PATH=/usr/lib/x86_64-linux-gnu/cmake/Qt6"
```

> 若 Qt 位于默认位置可被自动探测，直接 `make` 即可。Windows 下确保 ninja（或所用生成器）与编译器在 PATH 中。

## 直接使用 CMake

```bash
cmake -S . -B build -DCMAKE_PREFIX_PATH=<Qt安装路径> -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

### 各平台要点

- **Windows（MinGW）**：`-DCMAKE_PREFIX_PATH=C:\Qt\6.5.3\mingw_64`；产物 `build/typing.exe`。
  **源码/构建目录必须为纯 ASCII 路径**——MinGW + AUTOMOC 无法解析含中文的相对路径（工程已用 `typing` 命名）。
- **Windows（MSVC）**：`-DCMAKE_PREFIX_PATH=C:\Qt\6.5.3\msvc2019_64`，用 VS 开发者命令行或 `cmake --build`。
- **macOS**：`-DCMAKE_PREFIX_PATH=/opt/homebrew/opt/qt`；产物为 `typing.app`。
- **Linux**：`sudo apt install qt6-base-dev cmake g++`；`-DCMAKE_PREFIX_PATH=/usr/lib/x86_64-linux-gnu/cmake/Qt6`（或自动探测）。

## 运行

- 开发机：直接运行 `build/` 下的可执行文件（需 Qt 动态库在 PATH / 或使用 Qt Creator 运行）。
- 也可用 `make run`。

## 打包分发（make dist）

`make dist` 调用 `tools/package.py`：

- **Windows**：优先使用 `windeployqt`；找不到时**手动部署**——复制 `Qt6Core/Qt6Gui/Qt6Widgets.dll`、`platforms/qwindows.dll` 与 MinGW 运行库（`libgcc_s_seh-1.dll`、`libstdc++-6.dll`、`libwinpthread-1.dll`）。手动部署可显式指定路径：

  ```bash
  python tools/package.py --exe build/typing.exe --out dist \
      --qt C:/Qt/6.5.3/mingw_64 --compiler C:/Qt/Tools/mingw1120_64/bin
  ```

- **macOS**：对 `typing.app` 运行 `macdeployqt`（脚本尝试自动定位）。
- **Linux**：假定 Qt 来自系统包，只复制可执行文件（建议分发源码 + 构建说明，或使用 AppImage 等方案）。

产物位于 `dist/`，**整目录分发**（exe 与 DLL、`platforms/` 子目录缺一不可）。

> 已知坑：`windeployqt` 在部分 MinGW 环境报 “Unable to find the platform plugin” ——此时应使用手动部署路径（本工程已验证可独立运行）。

## CI 建议

- 每次提交可跑 `make selftest`（无界面，退出码即通过与否）。
- 产物即单一可执行文件 + 少量运行库，适合作为构建产物归档。

## 本机已验证的环境（2026-10）

- Windows 11，Qt 6.5.3（mingw_64）+ MinGW 11.2 + Ninja + CMake；
- `build/typing.exe` 与手动部署的 `dist/` 均验证可独立运行（干净 PATH 下双击启动正常）。
